## Evaluation rule and ablation

[`evaluate.py`](../evaluate.py) reuses the checked-in `fusion_channel.fusion_engine.compute_fused_scores` and `extract_highlight_windows` functions. It does not change model or fusion logic. Ablations set two modality weights to zero and retain the engine's per-channel normalization and top-k window selection:

| Variant | Visual weight | Audio weight | Speech weight |
|---|---:|---:|---:|
| Audio only | 0.0 | 1.0 | 0.0 |
| Speech only | 0.0 | 0.0 | 1.0 |
| Visual only | 1.0 | 0.0 | 0.0 |
| Full fusion | 0.4 | 0.4 | 0.2 |

A predicted interval matches a ground-truth interval when intersection-over-union (intersection duration / union duration) is at least 0.5. A maximum one-to-one bipartite match assigns true positives; unmatched predictions are false positives and unmatched annotations are false negatives. Precision = TP/(TP+FP), recall = TP/(TP+FN), and F1 = 2PR/(P+R). Precision or recall is `null` when its count denominator is zero; F1 is `null` when either input metric is undefined and is zero when both are zero. Positive timestamp labels are converted to one-second intervals `[t, t+1)`.

The current JSON reports include each available ablation's predicted windows, but all metrics are `null` because labels are missing. Thus there is no evidence-based metric comparison between modalities. For football, no channel inputs are supplied, so both predictions and metrics are unavailable.

## Reproduction commands

Run from the repository root. The test writes generated JSON and clip outputs under its working directory, so use a disposable project copy to preserve existing files.

```powershell
python test_pipeline.py
python -m pytest -q
python evaluate.py --sport cricket --visual visual_channel_output.json --audio audio_channel_output.json --speech speech_channel_output.json --output results/cricket.json
python evaluate.py --sport football --output results/football.json
```

The evaluator commands above deliberately omit `--ground-truth`; they reproduce the current `null` metrics. When independent annotations are available, supply them using `--ground-truth path.json`. For example:

```powershell
python evaluate.py --sport cricket --visual visual_channel_output.json --audio audio_channel_output.json --speech speech_channel_output.json --ground-truth "C:\data\cricket_ground_truth.json" --output results\cricket.json
```

The timing comes from the isolated `python test_pipeline.py` execution, measured with a wall-clock stopwatch around that command; no separate real-video benchmark command is claimed.

## Bugs and integration gaps observed (not fixed)

These are documented for review; no model logic or application code was changed:

1. The Flask replay/live worker invokes `main.py`, which only uses frame-difference motion detection. It does not run the audio, speech, or multimodal fusion modules, so the app does not deliver the multimodal pipeline described by its folder structure.
2. The API accepts an output directory and appends `--output_dir` to the `main.py` command, but `main.py` does not parse that option and writes to the hard-coded `output_highlights` directory.
3. The dashboard's file picker sets the text field to `file.name` but never uploads the file; a browser-local selection is not made available to the backend.
4. `training_weights.py` changes a motion threshold based on label density; it does not train or fine-tune a model despite the API naming.
5. `test_pipeline.py` has no assertions, so a successful run confirms execution/export only, not detection correctness.
6. `fusion_pipeline.py` and `fusion_channel/fusion_engine.py` implement different fusion algorithms and are not connected to the replay worker.

These issues were not fixed because the request explicitly asks to review and ask before changing bugs.
