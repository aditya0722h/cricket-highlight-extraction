## Part 2 — What is actually implemented

### Current branch architecture (`final-evaluation`)

```mermaid
flowchart TD
    VIDEO[Local video file]
    VIDEO --> V[Visual channel: OpenCV ~1 FPS]
    VIDEO --> A[Audio channel: FFmpeg mono 22.05 kHz]
    VIDEO --> S[Speech channel: PyAV mono 16 kHz]
    V --> VJSON[visual JSON: t, V_spatial, V_motion]
    A --> AJSON[audio JSON: t, STE, spectral_centroid, ZCR]
    S --> SJSON[speech JSON: t, transcript_segment, sentiment_score, keyword_hit, silence_after]
    VJSON --> F[Fusion engine: timestamp union + min-max + weighted score]
    AJSON --> F
    SJSON --> F
    F --> W[top-k non-overlapping sliding windows]
    W --> M[window metadata JSON]
    W --> E[FFmpeg stream-copy clip export]
    URL[HTTP(S) URL] --> API[Flask API + SQLAlchemy job records]
    PATH[Local path] --> API
    API --> THREAD[Background Python thread]
    THREAD --> MAIN[main.py frame-difference motion worker]
    MAIN --> MOVIEPY[MoviePy interval clips + concatenated reel]
    F -. "not invoked by Flask worker" .- API
```

The diagram distinguishes two separate implemented execution paths: standalone offline channels plus `fusion_channel/fusion_engine.py`, and Flask jobs plus motion-only `main.py`. The Flask worker does not wire the multimodal channel/fusion path. [`app/routes.py:56-119,146-184`; `main.py:57-190`; `fusion_channel/fusion_engine.py:32-89,92-133,151-245`]
