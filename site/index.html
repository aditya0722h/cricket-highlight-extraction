02 / The idea

Highlights are a signal-fusion problem.

Long matches contain far more footage than most viewers want to revisit, while meaningful moments can appear as motion, crowd/audio changes, or excited commentary. AutoHighlight samples these signals independently and aligns their timestamped features. A weighted fusion score ranks short, separated windows for review or export. The current system is a research prototype: cricket-oriented speech keywords are used for both sports, and the football path is not a football-event detector.

The evaluation selects at most three six-second windows, while each video has 61–68 pseudo-label intervals, which limits recall. The pseudo-labels come from matching visual embeddings against official highlight reels, so edits, transitions, replays, and unmatched scenes can make the labels noisy. Matches were not manually verified, so some apparent errors may be label errors. The current ranking setup and weights can also miss moments present in the pseudo-labels.

06 / Limitations & next steps

What the results say—and what to do next.

What’s implemented: The Flask worker uses a separate motion-only detector and is not connected to the multimodal fusion pipeline.

Next steps

  1. Create and manually review a human-labeled subset of match footage.
  2. Tune fusion weights using match-level held-out validation rather than the current pseudo-label split alone.
  3. Run and compare visual-only, audio-only, speech-only, and fused ablations against the same labels.

08 / Engineering notes

Challenges & what the code taught us.

01

Long-video memory is part of the design.

The speech channel uses a memory-mapped audio buffer and bounded feature batches; audio features are aggregated in chunks. Processing strategy matters as much as the model choice on long match footage.

02

One repo can contain distinct pipelines.

The multimodal fusion engine is an offline path, while the Flask worker calls a motion-only detector. Keeping that boundary explicit prevents the demo from implying the application already runs full fusion.

03

Generated evidence should not be overwritten.

The fusion exporter allocates incremented filenames when outputs already exist, with a regression test for preservation. Reproducible experiments need to retain previous clips and metadata.

09 / Next experiments

Make the evaluation stronger.

  • Collect and manually verify event annotations across more complete matches.
  • Evaluate on multiple held-out matches instead of relying on one cricket split.
  • Add football-specific features and vocabulary, then validate them on labeled football matches.
  • Connect multimodal fusion to the Flask job path and test the end-to-end app.

10 / Reproduce it

Run the pipeline locally.

Run from the repository root. FFmpeg must be on PATH; channel outputs and sample videos are local data.

01

Set up the Python environment

python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
02

Extract timestamped features

python benchmark_channels.py --video data\videos\cricket_full_match.mp4 --output-dir data\processed\cricket_full_match --model-size small
python benchmark_channels.py --video data\videos\football_full_match.mp4 --output-dir data\processed\football_full_match --model-size small

The benchmark reuses valid existing channel outputs. Add --force to recompute them.

03

Rank windows and render clips

python -c "from fusion_channel.fusion_engine import run_fusion_pipeline; run_fusion_pipeline(source_video=r'data\videos\cricket_full_match.mp4', vis_file=r'data\processed\cricket_full_match\visual_output.json', aud_file=r'data\processed\cricket_full_match\audio_output.json', speech_file=r'data\processed\cricket_full_match\speech_output.json', out_json=r'results\cricket_site_demo.json', top_k=3, window_sec=6.0)"
python -c "from fusion_channel.fusion_engine import run_fusion_pipeline; run_fusion_pipeline(source_video=r'data\videos\football_full_match.mp4', vis_file=r'data\processed\football_full_match\visual_output.json', aud_file=r'data\processed\football_full_match\audio_output.json', speech_file=r'data\processed\football_full_match\speech_output.json', out_json=r'results\football_site_demo.json', top_k=3, window_sec=6.0)"

Default weights are (0.4, 0.4, 0.2). Football uses the same generic pipeline, not football-specific event detection. Stream-copy clip boundaries may be approximate.
